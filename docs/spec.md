# Спецификация: Datamatrix Notepad

Статус: утверждено пользователем

Дата: 2026-07-25

Утверждено: 2026-07-25

Изменено: 2026-09-07 — добавлена поддержка UTF-16BE; GS (`U+001D`) сохраняется как часть кода.

## 1. Цель

Создать простую русскоязычную браузерную утилиту для Windows, которая:

1. Подключается к сканеру DataMatrix, работающему как последовательный (COM) порт.
2. Собирает принятые коды в именованные заметки.
3. Автоматически сохраняет заметки и настройки только в браузере.
4. Экспортирует содержимое каждой заметки в текстовый файл с вычисленным именем.
5. Разворачивается как статическое Blazor WebAssembly-приложение на GitHub Pages.

Целевой пользователь работает на одном компьютере в desktop-версии Chrome или Edge. Сервер, учётные записи и синхронизация между устройствами в MVP не предусмотрены.

## 2. Проверенные технические ограничения

### 2.1 Доступ к COM-порту

Blazor WebAssembly работает в браузерной песочнице, поэтому прямой доступ через `System.IO.Ports` невозможен. Доступ к сканеру выполняется через Web Serial API в JavaScript-модуле и Blazor JS interop.

Ограничения Web Serial API:

- API доступен только в поддерживающих его браузерах и только в secure context (HTTPS или localhost).
- Целевыми браузерами MVP являются desktop Chrome и Edge.
- Первый доступ к порту требует действия пользователя, например нажатия кнопки «Выбрать порт», после чего браузер показывает системный диалог.
- Одним вызовом пользователь разрешает доступ только к одному порту.
- Приложение может получить без нового диалога только те подключённые порты, доступ к которым пользователь уже разрешал этому сайту.
- Web Serial API не предоставляет надёжное системное имя вроде `COM4`. Для USB-устройств обычно доступны только VID и PID. В интерфейсе поэтому используется пользовательский псевдоним, например «Сканер», и технические VID/PID при их наличии.
- Разрешение браузера нельзя считать вечным. Приложение должно уметь запросить выбор порта повторно.

Следствие: сценарий «без разрешения прочитать все COM-порты и показать их системные имена» в Blazor WebAssembly на GitHub Pages нереализуем. Диагностика нескольких портов возможна только после отдельного разрешения каждого порта пользователем.

Официальные источники:

- [Web Serial API specification](https://wicg.github.io/serial/)
- [Web Serial API — Chrome for Developers](https://developer.chrome.com/docs/capabilities/serial)
- [Web Serial API — MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)
- [Blazor WebAssembly and JavaScript interop](https://learn.microsoft.com/en-us/aspnet/core/blazor/?view=aspnetcore-10.0)
- [HTTPS on GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)

### 2.2 GitHub Pages

GitHub Pages предоставляет HTTPS, поэтому удовлетворяет требованию secure context. При публикации необходимо учитывать базовый путь репозитория и обеспечить загрузку SPA при прямом открытии маршрута настроек.

## 3. Согласованные решения

Следующие решения подтверждены пользователем 2026-07-25:

1. Поддерживаются Windows 10/11 и desktop Chrome/Edge; Firefox, Safari и мобильные браузеры не входят в MVP.
2. В рабочем режиме открыт один активный порт.
3. В диагностике отображаются данные только одного выбранного активного порта. Подключение и одновременное чтение нескольких разрешённых портов не входит в MVP.
4. Параметры соединения по умолчанию: `9600 baud`, `8 data bits`, `no parity`, `1 stop bit`, `no flow control`.
5. Пользователь выбирает кодировку входного потока: UTF-8 (по умолчанию; ASCII является его совместимым подмножеством) или UTF-16BE. Выбранная кодировка применяется потоковым декодером при следующем подключении к порту.
6. Префикс по умолчанию пустой, суффикс — CRLF (`\r\n`).
7. Префикс и суффикс отделяют служебные символы и не сохраняются в заметке.
8. Каждый полностью принятый код добавляется в конец активной заметки отдельной строкой.
9. Экспорт создаёт UTF-8 файл с расширением `.txt`; содержимое файла равно тексту заметки.
10. Заметки и настройки хранятся в `localStorage` в версионированном JSON-формате.
11. Изменения автоматически сохраняются с debounce 300 мс; создание заметки сохраняется немедленно.
12. Заметка удаляется только по ручной команде пользователя и только после явного подтверждения.
13. Разделитель GS (`U+001D`) является частью содержимого кода и сохраняется в `[CODE]`, заметке и экспорте без изменений.

## 4. Пользовательские сценарии

### 4.1 Первичная настройка

1. Пользователь открывает приложение в Chrome или Edge.
2. Приложение проверяет наличие `navigator.serial`.
3. Если Web Serial недоступен, приложение показывает понятное сообщение о поддерживаемом браузере и не имитирует подключение.
4. Пользователь открывает страницу «Настройки».
5. Пользователь задаёт параметры последовательного соединения и выбирает входную кодировку UTF-8 или UTF-16BE.
6. Пользователь задаёт необязательный префикс и обязательный непустой суффикс либо выбирает готовый вариант CR, LF или CRLF.
7. Пользователь нажимает «Выбрать порт».
8. Браузер показывает системный диалог, в котором пользователь выбирает сканер.
9. Пользователь при необходимости задаёт порту псевдоним.
10. Приложение открывает порт с выбранными параметрами и показывает состояние «Подключён».

### 4.2 Диагностическое сканирование

1. На странице настроек пользователь включает или видит диагностический лог активного порта.
2. Пользователь сканирует тестовый код.
3. Лог показывает:
   - локальное время получения;
   - псевдоним порта и VID/PID, если они доступны;
   - декодированные данные;
   - управляющие символы в видимом виде: `\r`, `\n`, `\t`, `\u001D`;
   - собранный завершённый код либо состояние незавершённого буфера;
   - ошибки открытия, чтения и отключения.
4. Диагностический лог не сохраняется между сессиями и ограничивается последними 500 записями.
5. На странице настроек тестовые данные не добавляются в заметку.

### 4.3 Создание и редактирование заметки

1. На главной странице пользователь нажимает «Новая заметка».
2. Приложение создаёт заметку с уникальным идентификатором и немедленно сохраняет её.
3. Пользователь вводит название в отдельное однострочное поле.
4. Пользователь может вручную редактировать многострочное содержимое.
5. Каждое изменение названия или содержимого автоматически сохраняется.
6. Интерфейс показывает состояния «Сохранение…», «Сохранено» или ошибку сохранения.
7. Список заметок позволяет переключаться между созданными заметками и отсортирован по времени последнего изменения, новые сверху.
8. Пустое название разрешено; в списке оно отображается как «Без названия», но в данных остаётся пустым.
9. Пользователь может вручную запросить удаление выбранной заметки.
10. Перед удалением приложение показывает диалог подтверждения с названием заметки либо текстом «Без названия».
11. Отмена диалога не изменяет данные.
12. После подтверждения заметка удаляется и новое состояние сохраняется немедленно.
13. Если удалена активная заметка, приложение выбирает следующую доступную заметку; если заметок не осталось, отображается пустое состояние.

### 4.4 Сканирование в заметку

1. Пользователь выбирает активную заметку на главной странице.
2. Пользователь подключает ранее разрешённый порт либо выбирает его через системный диалог.
3. Последовательные байты могут приходить произвольными фрагментами; сборщик сохраняет буфер между чтениями.
4. Сборщик корректно распознаёт:
   - один код, разбитый между несколькими чтениями;
   - несколько кодов в одном чтении;
   - суффикс, разбитый между чтениями;
   - необязательный префикс;
   - отключение порта при незавершённом коде.
5. После обнаружения суффикса приложение удаляет служебные префикс и суффикс и добавляет код в конец содержимого активной заметки. GS (`U+001D`) внутри кода сохраняется.
6. Между кодами используется один символ новой строки `\n`; пустые завершённые коды не добавляются.
7. Дубликаты кодов разрешены и добавляются повторно.
8. Если активной заметки нет, код не теряется молча: приложение показывает предупреждение, но не создаёт заметку автоматически.
9. Полученный текст отображается как обычный текст и никогда не интерпретируется как HTML.

### 4.5 Восстановление после перезапуска

1. После перезагрузки страницы приложение восстанавливает заметки, активную заметку и настройки из браузерного хранилища.
2. Сохранённый объект порта не сериализуется.
3. Если браузер по-прежнему предоставляет ровно один ранее разрешённый порт, совпадающий с сохранёнными VID/PID, приложение может предложить или выполнить повторное подключение.
4. Если совпадений нет либо их несколько, пользователь выбирает порт заново.
5. Ошибка или несовместимая версия сохранённых данных не приводит к белому экрану; приложение сообщает об ошибке и не перезаписывает исходные данные автоматически.

### 4.6 Экспорт

1. Для активной заметки пользователь нажимает «Скачать».
2. Приложение вычисляет две части имени по первому подходящему совпадению в названии заметки:
   - `Часть1`: для паттерна `00ЦБ-(\d{6})` берутся только шесть цифр из группы; при отсутствии совпадения используется пустая строка;
   - `Часть2`: берётся первая корректная календарная дата, записанная точно как `dd.MM.yyyy`; при отсутствии совпадения используется пустая строка.
3. Предлагаемое имя файла: `{Часть1};{Часть2}.txt`.
4. Примеры:

| Название заметки | Имя файла |
|---|---|
| `Партия 00ЦБ-123456 от 25.07.2026` | `123456;25.07.2026.txt` |
| `Партия 00ЦБ-123456` | `123456;.txt` |
| `От 25.07.2026` | `;25.07.2026.txt` |
| `Произвольное название` | `;.txt` |
| `00ЦБ-12345 от 31.02.2026` | `;.txt` |

5. Содержимое скачивается как `text/plain` в UTF-8.
6. Экспорт не изменяет заметку и не отправляет данные в сеть.

## 5. Интерфейс

### 5.1 Общие требования

- Утилитарный адаптивный интерфейс без сложной графики и анимаций.
- Компоненты существующего пакета Microsoft Fluent UI используются там, где они упрощают доступность и единообразие.
- Все интерактивные элементы доступны с клавиатуры и имеют текстовые подписи.
- Состояние подключения всегда видно на главной странице.
- Ошибки показываются рядом с действием, которое их вызвало.

### 5.2 Главная страница

- Заголовок приложения.
- Кнопка перехода в настройки.
- Индикатор состояния порта и кнопка подключения/отключения.
- Список заметок.
- Кнопка «Новая заметка».
- Поле названия активной заметки.
- Многострочное поле содержимого.
- Индикатор автосохранения.
- Кнопка «Скачать».
- Кнопка «Удалить» с диалогом подтверждения.

### 5.3 Страница настроек

- Проверка поддержки Web Serial.
- Выбор/повторный выбор порта.
- Псевдоним порта.
- Baud rate.
- Data bits.
- Parity.
- Stop bits.
- Flow control.
- Префикс.
- Суффикс с готовыми вариантами CR, LF и CRLF.
- Кнопки подключения и отключения.
- Диагностический лог.
- Кнопка очистки только диагностического лога.

## 8. Команды

Команды выполняются из корня репозитория.

```powershell
# Локальный запуск
dotnet run --project ".\Datamatrix Notepad\Datamatrix Notepad.csproj"

# Сборка
dotnet build ".\Datamatrix Notepad.slnx" --configuration Release

# Тесты
dotnet test ".\Datamatrix Notepad.slnx" --configuration Release

# Проверка форматирования
dotnet format ".\Datamatrix Notepad.slnx" --verify-no-changes

# Публикация в локальную папку
dotnet publish ".\Datamatrix Notepad\Datamatrix Notepad.csproj" `
  --configuration Release `
  --output ".\artifacts\publish"
```

На момент создания черновика базовая Debug-сборка существующего проекта проходит с 0 ошибками и 0 предупреждениями. В ограниченной песочнице внутренний MSBuild task host не запускается; вне неё сборка проходит, поэтому это ограничение среды проверки, а не дефект проекта.

## 10. Стиль кода

- Публичные типы, свойства и методы: `PascalCase`.
- Локальные переменные и приватные поля: `camelCase`; приватные поля с `_`.
- Асинхронные методы получают суффикс `Async`.
- Nullable-аннотации не подавляются без обоснования.
- UI-компоненты не содержат парсинг фреймов или генерацию имён файлов; эта логика находится в тестируемых сервисах.
- Предпочтительны небольшие типы и явные зависимости вместо глобального состояния.
- Форматирование выполняется стандартным `dotnet format`.

## 11. Стратегия тестирования

### 11.1 Модульные тесты

Чистая C#-логика покрывается xUnit-тестами:

- парсинг `Часть1`;
- поиск и строгая проверка даты;
- отсутствие и несколько совпадений;
- сборка имени при пустых частях;
- фрейминг по CR, LF, CRLF и пользовательским значениям;
- несколько кодов в одном фрагменте;
- код и суффикс, разделённые между фрагментами;
- обработка префикса;
- пустой код;
- сериализация и чтение версии состояния.

Каждый граничный сценарий должен иметь отдельный читаемый тест.

### 11.2 Интеграционные проверки

- JS interop проверяется через заменяемые интерфейсы C# и тестовый источник последовательных фрагментов.
- Сохранение и восстановление проверяются в реальном Chromium с тестовыми заметками.
- Скачивание проверяется по имени, MIME-типу и байтам UTF-8.
- Неподдерживаемый браузер проверяется при отсутствии `navigator.serial`.

### 11.3 Ручная проверка с устройством

Перед выпуском обязательна проверка в Chrome или Edge с реальным сканером:

1. Разрешение порта.
2. Подключение с фактическими параметрами сканера.
3. Отображение CRLF в диагностическом логе.
4. Десять последовательных сканирований без потери и склейки кодов.
5. Отключение и повторное подключение USB.
6. Перезагрузка страницы и восстановление заметки.
7. Экспорт файла и проверка имени/содержимого.

Автоматические тесты не заменяют эту аппаратную проверку.

## 12. Границы

### Всегда

- Экранировать и отображать данные сканера как обычный текст.
- Обрабатывать отмену выбора порта, отключение устройства и ошибки чтения.
- Сохранять данные до навигации или закрытия вкладки, если есть ожидающее debounce-изменение.
- Запрашивать явное подтверждение перед удалением заметки и сохранять подтверждённое удаление немедленно.
- Выполнять тесты, форматирование и Release-сборку перед завершением задачи.
- Обновлять спецификацию до кода, если согласованное поведение меняется.
- Проверять работу в реальном Chromium.

### Сначала спросить

- Переход с `localStorage` на IndexedDB.
- Добавление runtime-зависимости.
- Одновременное чтение нескольких портов.
- Добавление массового удаления или очистки всех данных.
- Изменение формата экспорта или шаблона имени.
- Изменение GitHub Actions/Pages после первоначальной настройки.
- Переход с браузерного приложения на desktop/Blazor Hybrid.

### Никогда

- Не отправлять заметки, настройки и отсканированные данные на сервер.
- Не добавлять телеметрию без явного согласования.
- Не хранить ссылку на `SerialPort` как сериализуемые данные.
- Не интерпретировать данные сканера как HTML.
- Не проглатывать ошибки автосохранения или последовательного порта.
- Не удалять заметку без явного подтверждения пользователя.
- Не удалять пользовательские данные автоматически при ошибке миграции.
- Не публиковать секреты в репозитории или GitHub Pages.

## 13. Критерии готовности MVP

MVP считается функционально готовым, если одновременно выполнены условия:

1. Release-сборка и все автоматические тесты проходят без ошибок.
2. В Chrome и Edge приложение определяет поддержку Web Serial.
3. Пользователь может выбрать разрешённый порт и открыть его с заданными параметрами.
4. Диагностический лог показывает тестовый скан и видимые управляющие символы; GS виден как `\u001D` в `[RAW]` и `[CODE]`.
5. CRLF корректно завершает код даже при разделении между несколькими чтениями.
6. Десять последовательных сканов добавляются в активную заметку десятью отдельными строками.
7. Создание заметки сохраняется немедленно; изменения названия и текста сохраняются автоматически.
8. Запрос удаления показывает подтверждение: отмена сохраняет заметку, подтверждение удаляет её и немедленно сохраняет состояние.
9. После перезагрузки страницы заметки и настройки восстанавливаются.
10. Экспортные имена соответствуют всем примерам из раздела 4.6.
11. Экспортированный UTF-8 файл побайтно соответствует содержимому заметки.
12. Отмена выбора, занятый порт, отключение USB и недоступный Web Serial дают понятные ошибки и не повреждают заметки.
13. Приложение открывается с GitHub Pages по HTTPS и корректно загружает главную страницу и страницу настроек.
14. Проведена ручная проверка с реальным сканером.
15. Пользователь просмотрел и одобрил итоговое поведение перед публикацией.

## 14. Общий Definition of Done

Каждое изменение считается завершённым только когда:

- выполнены критерии приёмки конкретной задачи;
- новое поведение имеет тесты, которые не проходили бы без реализации;
- существующие тесты и Release-сборка проходят;
- проверены граничные и ошибочные сценарии;
- нет отладочного вывода, мёртвого кода и несвязанных рефакторингов;
- форматирование проходит;
- интеграция проверена в приложении, а браузерное поведение — в реальном браузере;
- пользовательское поведение и значимые архитектурные решения документированы;
- учтены безопасность, конфиденциальность и путь отката;
- пользователь одобрил изменение перед merge или deploy.

## 15. Открытые вопросы

Открытых вопросов, блокирующих планирование MVP, нет. Для MVP принят `localStorage`; если фактический объём данных приблизится к квоте браузера, переход на IndexedDB потребует отдельного согласования.
